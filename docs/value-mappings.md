# 精确值映射治理（策略 v3）

成功检测任务可在治理面板配置字段及“来源值 → 替换为”，例如“男 → M”。Spark 在标准化后的字段上精确匹配，区分大小写和空格。NULL 与未匹配值保持原值；留空输入框表示空字符串，不表示 NULL。

固定顺序：文本标准化 → 精确值映射 → 缺失值填充 → 移除仍缺失记录 → 去重 → 保存独立 CSV → 读取实际 CSV 复检。原始文件、已有版本与旧任务结果均保留。映射同一步只执行一次：A→B、B→C 会把原 A 变为 B、原 B 变为 C，不把原 A 连锁变成 C；新增填充值不会再次映射。

## 接口与快照

对成功任务调用 POST /api/tasks/{id}/govern：

~~~json
{
  "policyVersion": 3,
  "normalizations": {"status": "TRIM_UPPER"},
  "mappings": {
    "status": [
      {"from": "A", "to": "ACTIVE"},
      {"from": "B", "to": "BLOCKED"}
    ]
  },
  "fills": {"status": "UNKNOWN"},
  "dropMissing": false,
  "deduplicate": false
}
~~~

省略版本而携带非空 mappings 时，规范化为 v3。未配置映射的请求仍默认 v2，省略空 mappings，以保持已有 v2 快照形状；显式 v2 不能携带非空映射。支持显式 v3 组合其他策略。历史 v1/v2 任务的已保存策略和审计不修改。

字段必须存在。每字段 1～50 项，全请求最多 200 项，来源和目标合计最多 40000 个 UTF-16 单元；每个文本最多 1000 个 UTF-16 单元。来源按字段唯一，空字符串和纯空格都是有效来源/目标；不支持把值映射成 NULL。禁止 NUL、无效 Unicode 和完整的保留空值标记 \N。来源/目标必须是 JSON 字符串，不做数字、布尔或 null 强制转换；映射项只接受 from/to 两个字段。非法请求在创建任务前返回 400。

策略按字段和来源排序并深度冻结。映射会改变后续去重业务键，也可能引入新的空值、类型或格式异常；系统照常复检并在前后对比中呈现实际结果，不保证每种配置都会改善质量。未配置v4保留顺序时，去重仍为全字段字典序，不代表最新或业务最优记录；新保留顺序见 [业务去重保留优先级](retention-order.md)。

## 审计与报告

新增 VALUE_MAPPING 操作，包含 column、matchedRows、changedRows、entries。entries 逐项保存 from/to、匹配行数和实际改变行数。来源与目标相同时，匹配行数可非零而改变行数为零。每阶段计数基于该阶段输入，阶段之间不能相加当成去重后的受影响记录数。

逐项计数通过 Spark 聚合计算，转换使用 DataFrame 表达式，不在后端收集整表后替换。匹配与替换同时基于映射阶段开始时的原值，多个字段同样不会互相读取替换后的值。

任务详情、JSON 报告、生成版本与按原规则复检沿用已有持久化流程，无新增数据库表或迁移。页面可展开映射明细，区分空字符串/纯空格，展示命中与改变行数。

## 可复现验收

在本机服务运行后：

~~~bash
timeout 900 python3 tests/value_mappings.py
# 使用上一步输出的 fixture 路径，在受保护的空闲维护重启后执行：
timeout 120 python3 tests/value_mappings.py --check .runtime/value-mappings-具体ID.json
~~~

隔离副本可指定 --base http://127.0.0.1:动态端口/api。脚本仅新增合成 CSV、任务及版本，不删除已有数据。覆盖非法输入拒绝且不入队、非连锁精确映射、标准化/映射/填充顺序、NULL/空字符串/纯空格、中文/引号/换行/反斜线、无匹配与原值不变、组合移除及去重、零行版本、复检、报告、源数据不变与完整持久化快照。

测试生成的合成数据会保留。20 MiB 上传、单机 local[2]、串行任务和现有超时限制继续适用；本阶段没有进行分布式或 TB 级性能验证。
